## The Architecture

The BicameralMind has these components, from leaves inward:

```
BicameralMind
├── RightHemisphere (local, always-on, non-blocking)

│   │   ├── Experience (append-only event log)
│   │   ├── SpellExecution (deterministic pattern-match procedures)
│   │   └── affordance: consolidate, filtering
│   ├── Relevance (single filter used by both filtering and consolidation)
│   ├── affordance: continuous-attention (watches ContrastSpace)
│   └── affordance: recognize (shape → named sigil)
├── LeftHemisphere (remote LLM, stateless, invoked per-turn)
│   └── affordance: transmission (results written back to world)
├── CorpusCallosum / Gate (decides escalation)
│   └── invariants: amplitude-threshold, bounded-turn, coherence-precedence,
│       frequency-filtering, gate-authority, map-check
└── Memory
    ├── Recognition (recall, recognize-familiar-sigil)
    ├── Consolidation (consolidate, merge-sigils)
    ├── Decay (forget — passive, graph-based)
    └── Relevance (adaptive-familiarity)
```

## Why "all at once" decohereed

The system has deep interdependencies — the Gate reads Coherence before escalating, Memory needs Experience to consolidate, the LeftHemisphere needs Memory's vocabulary to generate within scope. Implementing everything simultaneously means every component is half-built and nothing can be tested in isolation.

## Strategy: leaves first, compose upward

The key insight from the spec is that several components are **self-contained** and can be implemented, tested, and verified independently. Here's my proposed order:

### Phase 1: Experience (the ground truth)
The simplest leaf. Append-only, causally-ordered, session-bounded, complete. It's a log. Four invariants, all easily testable:
- append-only: never delete or modify
- causal-ordering: entries in order
- session-bounded: sessions are distinct segments
- complete: every word recorded

This has **zero dependencies** on anything else. It's the foundation everything builds on.

### Phase 2: Memory store (geometric-storage + remember + recognize)
Memory as a data structure — positions in ContrastSpace with attached vocabulary (name, affordances, invariants). The affordances:
- `remember-a-sigil`: place a new position
- `recognize-familiar-sigil`: find nearest position, return vocabulary

Invariants: geometric-storage, reliable, vocabulary-retrieval. Still mostly a data structure with spatial queries. Depends on having embeddings but not on the rest of the system.

### Phase 3: Relevance filter (single mechanism)
One filter, used by both filtering and consolidation. The `single-mechanism` invariant demands this literally — there is one filter, not two. It takes a sigil and answers: relevant or not? `adaptive-familiarity` means repeated relevant encounters increase weight, irrelevant noise fades.

This can be tested in isolation with synthetic inputs.

### Phase 4: Subconscious (filtering + consolidation + spell execution)
Now compose: the Subconscious uses Experience + Relevance + Memory together.
- **Filtering**: as new Experience arrives, apply Relevance filter (same filter as consolidation — `single-mechanism`)
- **Consolidation**: during idle/sleep, review Experience through Relevance, compress into Memory (remember new, recognize familiar, merge co-occurring, forget unreinforced)
- **SpellExecution**: deterministic pattern matching, failure escalates

Critical invariant: `no-escalation` — the Subconscious never calls the LeftHemisphere directly.

### Phase 5: RightHemisphere (continuous attention + recognize)
Wraps the Subconscious. Watches ContrastSpace, senses disturbance. Invariants: non-blocking, conceptual-salience, semantic-stability. This is where embedding comparison lives — structure-level, not text-level diff.

### Phase 6: Gate (CorpusCallosum)
The decision point. Six invariants. Depends on RightHemisphere signals and Coherence readings. This is the most complex piece but by now everything it reads from exists and is tested.

### Phase 7: LeftHemisphere integration
Stateless, vocabulary-bounded, output-in-world. The LeftHemisphere itself is just "call the LLM with the right context." The hard part — which is the Gate's job — is already done.

### Phase 8: Sleep cycle
Ties it together: idle detection triggers consolidation. The `maintains-balance` invariant ensures oscillation between hemispheres.

---

## Why this order works

Each phase produces something **testable in isolation**:
- Phase 1: write events, read them back, verify ordering/completeness
- Phase 2: store sigils, query nearest, verify vocabulary comes back
- Phase 3: filter synthetic inputs, verify adaptive weight changes
- Phase 4: feed experience through filter, verify consolidation output
- Phase 5: feed edits, verify disturbance signals respect semantic-stability
- Phase 6: feed disturbance signals, verify gate decisions match invariants
- Phase 7: provide context to LLM, verify output stays vocabulary-bounded
- Phase 8: end-to-end cycle

Each phase is small enough to hold in one context window without decoherence.
