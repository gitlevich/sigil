# Spell

When I find myself performing  the same sequence of steps to achieve a routine goal, like releasing the application, I write a @spell: a deterministic algorithm defined in terms of its contract: input, output and optional side effects. 

A @spell is a single path, shortcut, through a @sigil to achieve a simple goal in a @timelike manner. 

A @spell allows me not to waste my attention on trivialities, but instead write a programmatic implementation in the most convenient language supported by my runtime, and only attend to the spell's contract. 

Alternatively, I can just write instructions to follow, as a prompt, and either follow them myself or task a simple agent to do it for me.
